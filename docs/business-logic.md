# MobilTracerの業務の流れと判断ルール

MobilTracerは、車両の状態・整備・修理・引き渡しの記録を残し、事業者と利用者が同じ内容を確認・共有できるようにするプロダクトです。

この資料は[要件定義書 v0.3.0](design.md)をもとに、予定する業務ルールを説明します。要件は顧客・提供側のレビュー待ちです。現在は車両・案件・記録・下書きの基本操作APIとTapyrusのローカル接続・検証環境まで実装しています。以下には、後続実装の業務処理も含みます。実装済みAPIの範囲は[API仕様](api.md)を参照してください。

## 車両ごとに、案件と記録を残す

一台の車両に、貸出・販売・修理などの案件を関連付けます。案件ごとに、貸出前や返却時などの記録と、その内容を識別する版を管理します。車両には内部IDを持たせ、ナンバーや所有者が変わっても履歴をたどれるようにします。

| 利用する事業者 | 記録する業務の流れ |
| --- | --- |
| レンタカー・カーシェア | 貸出前の状態を記録 → 利用者へ提示 → 返却時に比較 → 回答・異議を保存 |
| 販売店 | 仕入時の状態を記録 → 整備履歴を追加 → 許可した履歴を購入者へ提示 → 納車状態を確認 |
| 整備・修理業者 | 入庫状態を記録 → 見積・作業範囲の承認 → 作業を記録 → 引き渡し時に比較・確認 |

## 共通の処理は、記録・提出・回答・比較

1. 案件を作る。車両、担当者、利用者・所有者・承認者などを関連付けます。
2. 状態を記録する。写真原本、傷、点検結果、燃料、走行距離、備品などを保存します。必須項目の不足や添付失敗がある場合は、提出を止めます。撮影不能時の例外承認は、理由と承認者を残します。
3. 提出版を固定する。提出時点の内容・原本・提出者・日時・照合値を変更不可として保存します。相手が署名を拒否しても、提出版は残します。
4. 相手の回答を残す。閲覧、受領、状態への同意、作業承認を区別し、誰がどの版の何に回答したかを保存します。
5. 別の時点と比較する。貸出前後や修理前後の記録を並べ、人が差分と判断の根拠を残します。必要な写真がない場合は、比較できない理由を示します。

## 「完了」「同意」「登録済み」を混同しない

例えば返却が完了しても、利用者が車両の状態に同意したことや、チェーンへの登録が終わったことにはなりません。以下は同じ案件で同時に成立する表示例です。

| 管理するもの | 状態の例 |
| --- | --- |
| 業務 | 返却完了 |
| 記録 | 提出済みv2 |
| 利用者の回答 | 受領のみ・状態には未同意 |
| 異議 | 対応中 |
| チェーン登録 | 登録待ち |
| 内容の検証 | 未実施 |

判断時は次のルールを守ります。

- 無回答・署名拒否・期限超過を、同意や承認に変えません。
- 訂正は元の提出版を残して新しい版を作ります。旧版への署名を新版に流用しません。
- 修理の追加作業は、追加の承認を得てから着手します。
- 撮影箇所・必須項目・承認順・期限は顧客別に設定します。設定変更を、他社や提出済みの記録へ遡及させません。
- 共有する版・項目・相手・期間を指定します。所有者が変わっても、過去の利用者情報や他社の履歴を自動公開しません。
- 記録・原本は継続保存を基本とし、期間経過による自動削除は行いません。共有期限が切れても記録は保持します。個別の削除は理由と承認・実行の経緯を残し、圧縮・アーカイブは別途検討します。

## ハッシュで確認するのは、提出後の内容変更

記録版と写真原本のハッシュ（内容から計算する照合値）を、通常の編集とは別に保全した基準と照合します。写真そのものや直接識別できる個人情報はチェーンに載せず、ハッシュ等の最小情報を登録する案です。原本や基準が不足する場合は「検証不能」とします。

検証が一致しても、撮影内容の真実性、傷を付けた責任、請求の妥当性を証明したことにはなりません。登録失敗や応答喪失は業務完了と分けて保持し、再送する前に結果を照会して二重登録を防ぎます。

## 今回の実装で確認できること

| 実装状況 | 内容 |
| --- | --- |
| 実装・動作確認済み | 車両・案件・記録・下書きの基本操作、開発用認証と顧客・店舗・案件のアクセス制御、Go APIの稼働・接続準備状態の確認、Core・Esploraへの接続、検証用送金の承認・照会、再起動後のデータ保持 |
| 未実装 | 本番認証との接続、記録の提出・訂正、写真の保存・比較、回答・承認・共有、業務データのハッシュ登録・照合、登録状態の保存・再試行管理 |

詳細な業務ルールは[要件定義書の第6〜9章](design.md#6-三業態の代表的な業務フロー)、環境の起動と接続確認は[Tapyrusのローカル開発環境](tapyrus.md)を参照してください。
